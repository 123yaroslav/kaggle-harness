# Biohub - Cell Tracking During Development

Паспорт соревнования. Kaggle, code competition, спонсор Biohub SF, призовой фонд $60 000 на 7 мест (18/12/8/6/6/5/5 тыс.), медали и очки начисляются. Собрано по страницам соревнования (Description, Evaluation, Data, Code Requirements, Timeline, Rules). То, чего на страницах нет и что команда выяснила сама до дедлайна, помечено "по заметкам команды".

## Что предсказываем

Сэмпл - короткое 3D+t видео флуоресцентно меченых клеток эмбриона zebrafish. Хранится как Zarr v3, массив (T, Z, Y, X), обычно (100, 64, 256, 256), uint16, один чанк на кадр. Размер вокселя z=1.625, y=x=0.40625 µm. Нужно найти клетки в каждом кадре, связать их во времени и найти деления. Ответ - граф: узлы это детекции, ребра это связи между соседними кадрами, деление это узел с двумя и более исходящими ребрами.

Разметка есть только в train и лежит в .geff: целые координаты центроидов (t, z, y, x в вокселях) и ребра (source_id, target_id). Разметка разреженная, размечена только часть клеток. В метаданных каждого .geff есть estimated_number_of_nodes - оценка полного числа клеток в сэмпле, она входит в метрику.

Имя папки - {embryo_id}_{field_of_view}, первый сегмент это эмбрион. Train и test по эмбрионам не пересекаются.

По заметкам команды: в train 199 фильмов двух эмбрионов, 44b6 - 71 и 6bba - 128. Размеченных делений всего 151, в 112 фильмах их нет. Разметка покрывает 2.82% от estimated_number_of_nodes: 0.77% у 44b6 и 5.37% у 6bba, по фильмам от 0.13% до 20%.

## Формат сабмита

Файл submission.csv с заголовком `id,dataset,row_type,node_id,t,z,y,x,source_id,target_id`. Строки двух типов:

- node: node_id, t и целые z, y, x в вокселях; source_id и target_id равны -1
- edge: source_id и target_id ссылаются на node_id; остальные поля равны -1

id - сквозной счетчик строк. dataset - имя папки теста без .zarr. В сабмите должны быть все датасеты теста.

## Метрика

    score = adjusted_edge_jaccard + 0.1 * division_jaccard

Со страницы Evaluation:

- узлы предсказания и разметки сопоставляются в каждом кадре оптимальным паросочетанием по расстоянию между центроидами в микронах, не дальше 7.0 µm
- ребро считается TP, если оба его конца сопоставлены узлам разметки и между ними есть ребро разметки. Edge Jaccard = TP / (TP + FP + FN), дальше он умножается на штраф за лишние узлы
- деление: для каждого деления в разметке в предсказанном графе ищется компонента, которая покрывает стадию до деления и задевает обе дочерние ветви. TP/FP/FN по делениям дают Jaccard
- adjusted edge Jaccard усредняется по сэмплам с весом (TP + FP + FN), а счетчики делений суммируются по всем сэмплам (микро-усреднение)
- разреженность разметки метрика учитывает; скор может быть больше 1.0

По заметкам команды (разбор официального кода royerlab/kaggle-cell-tracking-competition и свой порт, сверенный с ним на 549 случаях без расхождений):

    J_i   = TP_i / (TP_i + FP_i + FN_i)
    m_i   = 1 - 0.1 * (N_pred_i - N_est_i) / N_est_i
    adj_i = max(0, J_i * m_i),   w_i = TP_i + FP_i + FN_i
    adj_edge = sum(w_i * adj_i) / sum(w_i)
    div_J    = sum(TP_div) / sum(TP_div + FP_div + FN_div)
    score    = adj_edge + 0.1 * div_J

- множитель m_i линейный и сверху не обрезан: +1% узлов стоит около -0.001 при J = 0.93, а при N_pred < N_est скор растет. N_pred - это все строки node, включая изолированные
- ребро участвует в подсчете, только если его источник сопоставлен узлу разметки с исходящим ребром или цель - узлу с входящим. Ребра между неразмеченными клетками и несопоставленные узлы не штрафуются ничем, кроме N_pred
- считаются только ребра t -> t+1, остальные молча выбрасываются. Дубли ребер схлопываются. У узла учитываются первые два исходящих ребра в порядке строк CSV
- деление засчитывается с допуском в один кадр в обе стороны. Форк вдали от размеченных клеток игнорируется, но форк с "испорченной" топологией (у ребенка есть второй родитель) - это FP в любом месте объема
- одно деление в разметке по весу равно нескольким сотням ребер, а делений мало (в train 0.76 на фильм), поэтому слагаемое делений шумное
- метрику организаторы правили 2026-07-17 (закрыли эксплойт с фиктивным узлом-хабом). Валидатор из публичных ноутбуков считает деления по старым правилам и завышает их примерно вдвое
- страница требует целые координаты, и это не формальность: проверяющий код усекает дробные. Посылка с координатами с тремя знаками после запятой получила 0.953 против 0.963 у той же посылки с округлением. Локальная эмуляция усечения дала -0.0074, другая команда на форуме получила -0.008
- обертка Kaggle вокруг метрики не опубликована

## Тест и паблик

Со страниц: в папке test лежат примеры (копии фильмов из train, без разметки). При реране ноутбука подставляется скрытый тест примерно того же размера, что и train. Публичный лидерборд считается по части скрытого теста, приватный - по остальной, какие данные куда попали, не раскрывается.

По заметкам команды:

- видимых фильмов в test четыре, по два от 44b6 и 6bba, это точные копии train
- скрытый тест оценивали в ~200 фильмов. Доля паблика по API соревнования - 29%, команда считала это как 58 фильмов в паблике и 142 в привате
- скор на лидерборде виден с тремя знаками после запятой
- эмбрионы скрытого теста в train не встречаются. Команда исходила из того, что это один новый, третий эмбрион. Сколько эмбрионов в тесте на самом деле и как они делятся между пабликом и приватом, организаторы не говорили. На форуме один участник писал про два эмбриона, без источника
- по размеру submission.csv на скрытом тесте (около 3.9 млн строк) выходит примерно 10 тыс. узлов на фильм - втрое меньше, чем в среднем на четырех видимых

## Ограничения

- сабмит только ноутбуком. CPU или GPU, не дольше 12 часов, интернет выключен, результат в submission.csv
- внешние данные и предобученные модели разрешены, если они публичны и бесплатны для всех участников. Делиться кодом вне команды приватно нельзя
- 5 посылок в день, 2 финальные. Если их не выбрать, Kaggle выберет сам. При равенстве скоров выше та посылка, что отправлена раньше
- команда до 5 человек. Победители отдают код обучения и инференса под лицензией MIT

По заметкам команды: реран на скрытом тесте на 2xT4 занимал 6.6-7.9 часа, один раз 8.7. Должна ли посылка досчитаться до дедлайна, организаторы не ответили; на форуме отвечали, что должна.
