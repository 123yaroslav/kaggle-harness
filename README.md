# Harness для ML-соревнований

Прототип обвязки вокруг LLM для соревнований на Kaggle. Диспетчер получает запрос, строит план и раздает шаги пяти субагентам. На каждый шаг он выбирает из каталога методику (скилл), и ее текст попадает в системный промпт субагента только на этот шаг.

Домен свой. Скиллы написаны по разбору моего участия в Biohub Cell Tracking: на паблике было 19-е место, на привате 49-е, потому что решения принимались по публичному лидерборду. Отсюда главное в обвязке: решать по валидации, а самые важные правила держать в коде, а не в промптах.

Стек: Python, LangGraph (графы диспетчера и субагента), Pydantic (состояние графов, ход диспетчера, аргументы инструментов), LiteLLM (живая модель).

## Запуск

    pip install -r requirements.txt
    python main.py

Ключи не нужны: кейсы идут на записанных ответах модели (claude-opus-5-5), около двух минут. Инструменты при этом выполняются по-настоящему: код субагентов запускается, метрика и бутстрап считаются. Проверено на Python 3.12.

    python main.py --case biohub_final_picks              # один кейс
    python main.py --case biohub_line_review --no-skills  # тот же запрос, но скиллы в промпт не попадают
    python main.py --llm live                             # живая модель через LiteLLM, ключ провайдера в окружении

## Схема

    запрос
      |
    Dispatcher: граф LangGraph plan <-> delegate, инструментов нет
      |   plan: видит запрос, итоги шагов, свой прошлый план и каталоги субагентов и скиллов (названия и описания).
      |         Ответ - JSON, разбирается в pydantic-модель DispatcherAction
      |   delegate: SkillStorage.get(skill_nm) -> текст скилла -> системный промпт субагента на один шаг
      v
    SubAgent: граф LangGraph think <-> act
      |   think: модель вызывает инструмент или дает ответ
      |   act: ToolStorage.call, аргументы проверяет pydantic-модель инструмента
      v
    выжимка шага + факты от harness (вердикты, выбор, новые прогоны) -> обратно в plan

| субагент | за что отвечает | свои инструменты |
|---|---|---|
| scout | факты о соревновании и о состоянии команды | Kaggle API на чтение |
| validation_engineer | каким локальным цифрам можно верить, шум валидации и паблика | lb_noise, compare_runs |
| experiment_engineer | код, новые прогоны | register_run |
| auditor | утечки, подгонка, клоны; вердикт по каждому прогону | set_verdict |
| strategist | что принять и что финалить | set_final_picks, set_line_review |

Файлы рабочей папки читают все, `run_python` есть у всех, кроме разведчика. Метапромпт - `dispatcher_prompt_template` в `harness/dispatcher.py`, роли - в `harness/agents/`.

Скилл - .md файл в `skills/` с шапкой `name` и `description`, всего их 10. Код про конкретные скиллы ничего не знает, новый скилл - это новый файл. Один и тот же субагент получает разные методики: стратег - `final_picks` при выборе финальных, `change_acceptance` при разборе решений, `lever_priority` и `code_competition_submit` при планировании.

В коде, а не в промпте: финальным может стать только отправленный прогон с вердиктом аудитора "принять"; посылок harness не делает, Kaggle доступен только разведчику и только на чтение; у кода субагентов окружение без ключей; приватные скоры в рабочую папку и в промпты не попадают.

## Кейсы

Два кейса идут на настоящем состоянии моей команды в Biohub за полчаса до дедлайна: 40 посылок, журнал решений, 19 дорожек локальной валидации. Приватные скоры лежат отдельно, по ним harness сверяет результат после прогона.

| кейс | что просят | что получилось |
|---|---|---|
| biohub_final_picks | отметить 2 финальных сабмита, команда предлагает FA и TP2 | пара команды отклонена как два клона одной линии, вторым слотом взят прогон с другой головой координат. На привате 0.936 против 0.935 у моего реального выбора, разница внутри шума |
| biohub_gate_experiment | проверить идею гибрида двух прогонов и сказать, стоило ли тратить посылку | работают все пять субагентов: инженер экспериментов собирает и регистрирует гибрид, аудитор и стратег его разбирают |
| biohub_line_review | разобрать прошлые решения "принять/закрыть" до того, как откроется приват | из 26 решений команда права по привату в 14, разбор в 17; без скиллов 16 и 17 из 23 |
| rsna_day1 | план первой недели в соревновании, которое идет сейчас | разведчик читает Kaggle API, диспетчер по ходу вставляет второй заход разведчика, план в `workdir/rsna_day1/notes/PLAN.md` |

## Лог

Кусок вывода `python main.py --case biohub_final_picks`, строки обрезаны:

    [dispatcher] ход 4: Факты собраны, инженер валидации оценил доверие к дорожкам и шум, аудитор вынес вердикты всем 40 прогонам ...
        план 1: strategist: выбрать и записать 2 финальных сабмита с пререгистрацией
    [dispatcher] шаг 4 -> strategist, скиллы: final_picks, контекст: шаги [1, 2, 3]
    [strategist] вызван. Скиллы в системном промпте: final_picks (3448 из 8004 символов)
    [strategist] инструмент compare_runs  {"base": "V12", "cand": "FA", "lane": "honest_oofm"} -> 738 симв.
    [strategist] инструмент lb_noise  {"base": "V12", "cand_list": ["V12O", "LNK"], "lane": "audit8"} -> 386 симв.
    [strategist] инструмент set_final_picks  {"pick_list": [{"run": "FA", "reason": "Слот 1 - лучший представитель основной линии ... -> 39 симв.
    [strategist] итог (8 вызовов инструментов): - Финальными отмечены FA (слот 1) и V12O (слот 2) ...
    - Пара команды FA + TP2 отклонена: это клоны семейства V12, а разница P(золото) 0.411 против 0.393 получена моделью, подогнанной под табло.
    [harness] финальный выбор принят и записан в notes/final_picks.md вместе с пререгистрацией: ['FA', 'V12O']

Ответ стратега идет по скиллу: в `skills/final_picks.md` написано, что клоны занимают один слот, что отвергнутые по паблику внутри шума возвращаются в кандидаты и что выбор не строится на модели, подогнанной под табло. Полные трейсы лежат в `traces/`: `<кейс>.md` читать глазами (метапромпт, системный промпт каждого субагента вместе со скиллом, каждое сообщение модели и результат инструмента), `<кейс>.jsonl` - те же события целиком.

## Что не сделано

- Каждая цифра - один прогон, а разницы на привате меньше шума. Пользу скиллов сравнение "со скиллами и без" на одном прогоне не доказывает.
- Скиллы написаны по тому же Biohub, на котором идут кейсы: это проверка задним числом. Перенос только в rsna_day1.
- `run_python` - не песочница: процесс без ключей, но диск и сеть ему доступны.
- Обучения и посылок нет, live-режим через LiteLLM проверен только на заглушке, записи сделаны через claude CLI.

Подробнее про кейсы, метки прогонов и ограничения - в `docs/NOTES.md`.
